## 1. KONTEKS & TUJUAN APLIKASI
**SIMPATIK** adalah *spatial utility tool* (alat kerja pencocokan titik koordinat X & Y universal).
- **Kasus Utama:** Mencocokkan, mengoreksi, dan mengonfirmasi data **Trafo** (yang selalu memiliki Deskripsi/Kode Unik serta Koordinat X & Y) terhadap data Master.
- **Sifat Universal:** Aplikasi ini bebas digunakan untuk data apa saja selama memiliki Koordinat (X & Y). Misalnya seseorang ingin mencocokkan data PDPJ terhadap banyak Master sekaligus (Master DIL, Prabayar, Pascabayar). Jika bahan Master belum ada, user tinggal *upload* dan beri nama/kategori. Jika sudah ada di "Gudang Master", user tinggal mencentang Master mana saja yang mau dijadikan acuan.
- **Penanganan Kondisi Tanpa Deskripsi (Instruksi Khusus):**
  - Jika Data B (data yang ditinjau, misal sebagian data lapangan/PDPJ) **memiliki Deskripsi B**, sistem mencocokkan Kode Unik terlebih dahulu (`Deskripsi A == Deskripsi B`), lalu menghitung jarak koordinatnya.
  - Jika Data B **TIDAK memiliki Deskripsi B** (kolom kosong atau memang hanya daftar koordinat X & Y mentah), sistem **TETAP BISA MENCOCOKKAN** secara otomatis menggunakan *Spatial Nearest Neighbor* (mencari titik Master A terdekat dalam radius toleransi) tanpa mengharuskan Data Master kehilangan Deskripsi A-nya. Justru Deskripsi A dari Master akan direkomendasikan sebagai identitas untuk titik B tersebut.

## 2. TECH STACK & ARSITEKTUR
- **Framework:** Next.js (App Router) + TypeScript
- **Styling & Motion:** Tailwind CSS + Shadcn UI (dimodifikasi menjadi *floating glass panels*) + **Framer Motion** (untuk animasi komponen, *hover dock*, dan *intro/auth motion graphics* 1–3 detik).
- **Map & 3D Engine:** **MapLibre GL JS** + **Deck.gl** (menggunakan WebGL Canvas agar mampu merender puluhan ribu titik di 60 FPS, mendukung *camera pitch tilt* 45–60 derajat, *Bounding Box Culling*, dan garis lengkung 3D / *ArcLayer*).
- **Tabel Data:** `@tanstack/react-table` + `@tanstack/react-virtual` (wajib *virtualized row* agar *scroll* puluhan ribu baris tidak *lag*).
- **Database & Backend:** PostgreSQL + **PostGIS Extension** (akses via Prisma ORM + `$queryRaw` untuk operasi geospasial `ST_DistanceSphere` dan `GIST Index`).
- **File Parser:** `xlsx` (SheetJS) / `papaparse` untuk membaca Excel multi-sheet puluhan ribu baris secara *chunking/batching*.

## 6. LOGIKA BACKEND, ALGORITMA PENCOCOKAN & OPTIMASI SKALA BESAR

### A. Upload Multi-Sheet & Auto-Sanitizer (`bersihkan-data.ts`)

1. Saat user memilih file Excel (`.xlsx` / `.csv`), tampilkan daftar _Sheet_ yang ada di dalamnya.
    
2. User memilih _Sheet_ dan memetakan kolom mana yang menjadi **Deskripsi**, **Koordinat X (Longitude)**, dan **Koordinat Y (Latitude)**. Untuk Data B, pilihan kolom Deskripsi boleh dikosongkan ("Tanpa Deskripsi").
    
3. **Auto-Fix Koordinat Ketukar:** Di Indonesia, Longitude (X) bernilai sekitar `95.0` s/d `141.0` dan Latitude (Y) bernilai `-11.0` s/d `6.0`. Jika terdeteksi nilai X dan Y terbalik, otomatis tukar nilainya dan beri notifikasi ke user. Ubah koma desimal (`-6,712`) menjadi titik (`-6.712`).
    
4. **Chunked Insertion:** Potong puluhan ribu baris menjadi _batch_ @ 2.500 baris per transaksi database agar hemat memori dan tampilkan _progress bar_ real-time. Jangan simpan file Excel mentah di storage server setelah diekstrak!
    

### B. Hybrid Matching Engine (`cocokkan/route.ts`)

Saat user mencentang satu atau beberapa Master (misal Master Trafo, atau gabungan DIL + Prabayar + Pascabayar) dan klik **"Mulai Pencocokan"**, jalankan 2 tahap SQL PostGIS:

1. **Tahap 1 — Pencocokan Kode Unik (Untuk Data B yang Punya Deskripsi B):**
    
    - Cocokkan `B.deskripsi_b_bersih = A.deskripsi_a_bersih` pada `master_id` yang dipilih.
        
    - Jika kode unik yang sama ditemukan di lebih dari satu Master, pilih yang jarak spasialnya paling dekat menggunakan `DISTINCT ON (B.id) ... ORDER BY ST_DistanceSphere(B.geom, A.geom) ASC`.
        
    - Hitung `jarak_meter`. Jika `jarak_meter <= toleransi_meter`, set `status_keterangan = 'AKURAT'`. Jika lebih besar dari toleransi, set `status_keterangan = 'PERLU_KOREKSI_JARAK'`.
        
2. **Tahap 2 — Pencocokan Spasial Terdekat / KNN (Khusus Data B Tanpa Deskripsi B atau Kode Tidak Ketemu):**
    
    - Untuk baris B yang `deskripsi_b` kosong ATAU belum mendapat pasangan di Tahap 1, gunakan operator indeks spasial PostGIS `<->` (`LATERAL JOIN`) untuk mencari 1 titik Master A terdekat dalam radius maksimal `100 meter`.
        
    - Jika ketemu dalam radius tersebut, pasangkan dengan titik Master A itu, isi `deskripsi_a` & `sumber_master` dari Master A, hitung `jarak_meter`, dan beri status `KANDIDAT_LOKASI_TERDEKAT` (agar user tinggal klik "Terima Deskripsi Master" saat konfirmasi).
        
    - Jika di radius 100 meter tidak ada titik Master sama sekali, beri status `TIDAK_DITEMUKAN`.
        

### C. Teknik "Frustum Culling" Kamera Peta (`titik-peta/route.ts`)

- Jangan pernah memuat semua puluhan ribu titik ke peta sekaligus!
    
- Setiap kamera peta digeser/di-zoom, kirim koordinat batas layar (`minX, minY, maxX, maxY, zoom`) ke backend.
    
- Backend memfilter titik menggunakan `ST_MakeEnvelope(minX, minY, maxX, maxY, 4326)` sehingga hanya merender titik yang berada di pandangan mata user (persis sistem render kamera game MMORPG).
